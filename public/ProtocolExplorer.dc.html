AXI4 splits one transfer across five independent channels — AW carries a write address out and W its data, B returns the one write response, AR carries a read address out and R brings the data back. Every channel is the same VALID/READY handshake: the source asserts VALID, the destination asserts READY, and the transfer happens on the rising edge where both are high.

A manager is never wired to a subordinate directly. The interconnect is the block in between, and it exists because address ownership has to be resolved somewhere: it holds the address map, works out which subordinate a transfer belongs to, and joins the two sets of channels together for as long as that transfer lasts. To the CPU it looks like one subordinate covering the whole address space; to SRAM0 it looks like one manager.

This network is mux-based, not packet-switched. A NIC-400 does not wrap a transfer in a header and forward it hop by hop — it is a crossbar of dedicated per-channel wires with an address decoder and an arbiter in front of each port. A channel that is not selected simply sits idle.

Every block is clickable. Press READ or WRITE on the CPU, pick a target address, then press 1 CLK to advance the model one cycle. Amber on a wire is VALID high with READY low — a wait cycle. Grey wires are idle and never move.

1 · DECODE
It reads AWADDR or ARADDR and works out which subordinate owns that address. The map is fixed when the NIC-400 is configured — nothing is learned or routed at run time.
2 · CONNECT
It muxes each of the manager's five channels onto the matching channel of that subordinate, one channel at a time, and arbitrates when two managers want the same port.
3 · ANSWER
It guarantees a response. B or R comes back for every transfer the manager issues — DECERR when no region matched, because a manager cannot withdraw a transfer and must never be left waiting.

NIC-400CoreLink Network Interconnect — the configurable AXI crossbar between managers and subordinates.
ASIBAXI Slave Interface Block — the interconnect port a manager plugs into. The block name keeps the older word; the role is the subordinate end of that link, answering READY to the CPU. One per manager.
AMIBAXI Master Interface Block — the interconnect port that drives a subordinate. Its role is the manager end of that link: it asserts VALID and waits for READY. One per subordinate port.
splitterThe decode and fan-out stage inside the NIC-400. Combinational address matching — no table, no header, no store-and-forward.
default
subordinateThe responder that answers an address no region matched, so the manager always gets a response. The NIC-400 TRM calls it the default slave.
manager
subordinateAXI4 names for the two ends of a link — the side that issues transfers and the side that answers. Documents before AMBA AXI issue H say master and slave, which is why ASIB and AMIB keep those letters.
arbiterThe selection stage in front of a subordinate-facing port. Two managers requesting it in one cycle get one grant; the grant covers a whole transfer, so nothing is interleaved. Drawn at L3.
AxQOSAWQOS and ARQOS — a four-bit priority hint the manager issues with the address. An arbiter set to QoS priority grants the higher value first; one set to round-robin ignores it.
burst · beatA burst is one transaction; a beat is one data transfer inside it. One address transfer describes the whole burst, and AxLEN + 1 beats follow on the data channel.
AxID · RIDAWID and ARID tag a transaction; RID and BID come back on the response so you can tell which one finished. Same ID must stay in order, different IDs need not.
OKAYBRESP or RRESP = 0b00. The transfer completed normally.
DECERRDecode error, BRESP or RRESP = 0b11. No region owns the address; the interconnect answers instead of a subordinate.
WHY A TRANSACTION NEEDS A TAG
Until now the manager had one transaction outstanding, so a returning response could only belong to it — order alone identified it. Two at once breaks that, because B and R carry no address: neither channel has a field saying which transfer it answers.
So the address channel carries a tag — AWID / ARID — and every response quotes it back as BID / RID. The tag is the only thing tying an answer to its question, which is what lets responses arrive in any order.
The tag is payload on the address channel, so it travels the whole path and is visible on every hop. ASIB0 does not keep it — it records which IDs are outstanding so it knows where to send a response, then forwards AxID onward unchanged. The subordinate is what quotes it back.
